# 반도체 공정 이상 검토·검증·승인 사용 사례

## 상태와 목적

**설계 문서이며 실행 기능·현장 검증 결과가 아니다.** 기존 SECOM 실험, 데이터 분할, 평가 수치와 모델은 변경하지 않는다. 실제 MES·SPC·FDC 연결, wafer map 분석, 공정 원인 규명, 조치·승인 저장은 이 문서로 구현되지 않는다.

FabGuard의 현재 역할은 공개 데이터의 생산 건별 위험순위와 익명 변수 점검 후보를 제공하는 것이다. 아래는 이를 공정·설비·PE·품질 엔지니어의 업무에 연결하기 위한 목표 사용 사례다. Fledge 로컬 수집 검증과 PV 데이터 품질 검증은 실제 반도체 현장 성능의 증거가 아니다.

## 목표 업무 흐름과 책임

| 단계 | 필요한 증거 | 목표 담당 역할 | FabGuard 경계 |
|---|---|---|---|
| 신호 접수 | 시점·단위·출처가 있는 측정값, SPC 경보 또는 검사 결과 | 공정·검사 담당 | 입력 계약을 통과한 기록만 분석 후보로 사용 |
| 우선 검토 | 점검예산, 위험순위, 모델·입력 버전 | 공정·PE | 점검 순서 제안; 합격·불합격이나 원인 확정 금지 |
| 원인 후보 검토 | 설비 이력, 공정 변경, 검사·센서의 시간 관계 | 공정·설비·소자 | 실제 변수 사전과 맥락이 없으면 익명 후보로 유지 |
| 검증 계획 | 대조 조건, 평가 항목, 부작용·중단 기준 | 공정·PE·품질 | 모델 점수를 조치 승인으로 취급하지 않음 |
| 검증 평가 | 실험 결과, 품질·신뢰성 항목, 실패·불확실성 | 해당 전문 엔지니어 | 개선 효과와 부작용을 분리 기록하는 목표 |
| 승인·후속 추적 | 승인 권한, 판단 근거, 조치·롤백·추적 결과 | 사업장 지정 승인자 | 자동 recipe 변경·설비 정지·재가동·출하 승인 없음 |

담당 역할은 예시이며 사업장별 책임 분장으로 확정해야 한다. 승인 기록 자체와 인증·권한 검증은 별도 요구사항이다. 현재 구현된 승인 워크플로가 있다고 해석하지 않는다.

## 사례 A: 공정·설비 이상 후 점검 우선순위

공정 계측 결과의 이상 신호와 장비 센서의 시간 변화를 함께 확인해야 하는 상황을 가정한다.

- 목표 입력: 공정 계측값, 장비 센서값, lot·wafer·tool·chamber·recipe 식별자와 공정 수행 시각.
- 목표 출력: 엔지니어가 먼저 확인할 기록과 관련 증거의 목록.
- 확인 절차: 측정 오류와 매핑 오류를 먼저 배제하고, 설비 정비·공정 변경 이력 및 검사 결과와 대조한다.
- 검증 조건: 조치 전 비교 조건과 허용 기준을 정하고, 시험 결과가 부족하거나 부작용이 있으면 미해결로 남긴다.
- 경계: SPC는 공정 결과 관리, FDC는 장비 센서 감시에 관한 업무 맥락이다. FabGuard가 두 시스템을 구현하거나 대체한다는 뜻이 아니다. 익명 SECOM 변수를 온도·압력·CD로 바꾸어 부르지 않는다.

## 사례 B: PE·품질의 추가 검사 후보 선별

검사 여력이 제한된 상황에서 추가 확인할 생산 건을 정하는 시나리오다.

- 목표 입력: 승인된 WT/PKT 결과, test bin 정의, 재검사 이력, 라벨 확정 시각.
- 평가: 동일한 점검예산에서 포착·누락·불필요 점검을 기준선과 비교한다.
- 누출 방지: 점수 산출 시점 이후의 검사·최종 품질 결과는 입력 특성으로 사용하지 않는다.
- 경계: 현재 SECOM Top-K 결과는 WT/PKT screening 성능이나 실제 출하 품질 보증이 아니다. 검사 프로그램·spec·출하 판정은 해당 담당자의 권한이다.

## 사례 C: 적층·패키징 변경의 검증 증거 관리

적층 구조나 공정 조건 변경 시 목표 특성과 다른 품질·신뢰성 항목을 함께 검토하는 미래 설계 사례다.

- 변경 이유와 대조 조건을 먼저 기록한다.
- 목표 특성, 부작용 항목, 측정 방법, 중단·롤백 기준을 실험 전에 정한다.
- 개선·악화·불확실한 결과를 각각 보존하고 공정·소자·품질 담당자가 검토한다.
- 경계: warpage·HBM·NAND는 적용 맥락 예시일 뿐이다. 물리 예측 모델, recipe 최적화 또는 HBM 검증을 수행한 것이 아니다. 합성 사례도 제조 성과 증거로 사용하지 않는다.

## 현장 데이터 계약 초안

아래는 향후 데이터 확보 시 검토할 항목이며 현재 어댑터의 확정 스키마가 아니다.

| 항목 | 요구사항 |
|---|---|
| 식별자 | source_record_id, lot_id, wafer_id, tool_id, chamber_id, recipe_version, process_step; 실제 출처와 연결 가능한 값만 사용 |
| 시간 | event_time, available_at, label_finalized_at; 시간대 명시, 점수 산출 시점에 이용 가능했던 데이터만 입력 |
| 측정 | 이름·단위·결측 의미·허용범위·교정 및 변수 사전 버전; 비유한 값은 정상 측정으로 승인하지 않음 |
| 판단 | review_id, 입력·모델 버전, 점검예산, 후보 근거; 연관 신호와 물리 원인을 구분 |
| 검증 | 비교 조건, 사전 기준, 결과, 부작용, 중단·롤백 판단, 증거 위치 |
| 책임 | 검토·승인 역할, 시각, 이유; 기록과 실제 인증·권한 검증을 구분 |

식별자가 없으면 추정해 채우지 않는다. SECOM 생산 건을 실제 lot 또는 wafer라고 단정하지 않는다. 기록 결합에는 일대다 관계, 지연 도착, 재검사와 중복 처리 기준이 필요하다.

## 향후 구현의 인수 조건

1. 실제 변수 사전·식별자·시간 관계와 사용 권한이 확보되지 않으면 현장 연결 완료로 표시하지 않는다.
2. 비정상 입력은 안전하게 격리하며, 출력 장애 시 정상 기록이 복구 불가능하게 처리 완료로 소모되지 않도록 별도 실행 테스트로 확인한다.
3. 검토·검증·승인 이력은 저장 실패·재시작·재시도까지 시험한다. 이 문서만으로 충족됐다고 표시하지 않는다.
4. 모델 출력에서 설비 제어나 recipe 변경으로 이어지는 자동 실행 경로를 만들지 않는다.
5. 독립 데이터의 위험순위 성능과 현장 조치 효과를 별도로 평가한다. 단순 전후 비교나 PV 품질 점수를 반도체 수율 개선으로 전용하지 않는다.
