# FabGuard 도메인 전문가 검토 워크플로우 초안

상태: **현장 도입 전 운영 설계안**. FabGuard V1은 공개 SECOM 데이터의 오프라인 실험이며, 아래 절차는 실제 공장·품질시스템에서 승인되거나 실행된 표준작업절차(SOP)가 아니다.

## 목적과 적용 경계

이 워크플로우는 FabGuard의 Top-K 위험순위를 공정·품질 엔지니어가 검토 가능한 작업 단위로 전달하고, 확인 근거와 후속 결정을 추적 가능하게 남기는 최소 절차를 정의한다.

- 모델 출력은 **점검 순서 제안**이며 불량 판정, 원인 규명 또는 설비 제어 명령이 아니다.
- 익명 SECOM 변수는 실제 센서·설비·공정 항목으로 간주하지 않는다.
- 기존 필수 검사, 품질 승인, 보류·폐기·recipe 변경 권한은 그대로 유지한다.
- 현장 적용 전 실제 조직의 데이터 사전, 권한, 교대 방식과 품질 기준서로 대체·승인해야 한다.

## 참여 역할과 인수인계

| 역할 | 제공하거나 확인할 내용 | 결정권 경계 |
|---|---|---|
| 모델·시스템 담당자 | 큐 생성시각, 모델·입력 버전과 해시, 점검예산, 위험순위, 데이터 품질·드리프트 상태 | 생산 건의 품질 상태나 공정조치를 확정하지 않음 |
| 공정 엔지니어 | 공정 단계, tool·chamber·recipe, 변수 사전, 변동점·정비·교대 이력 대조 | 승인 범위 안에서 추가 조사 제안; 품질 최종판정은 조직 기준을 따름 |
| 품질 엔지니어 | 검사·재검사 이력, defect·hold·release 기준, 유사 Lot 영향 범위 확인 | 보류·해제·재검사 등 품질조치 승인 |
| 생산 운영 책임자 | 점검 가능 인력·시간, 생산 영향, 교대 인수인계와 에스컬레이션 조정 | 모델 점수만으로 필수 절차를 생략하거나 점검예산을 임의 확대하지 않음 |
| 데이터 담당자 | 식별자 연결, timestamp·단위·결측·지연·계보 확인 | 계약 위반 데이터를 임의 보정해 정상 입력처럼 통과시키지 않음 |

한 사람이 여러 역할을 맡는 조직에서도 각 판단이 어느 역할의 권한으로 이루어졌는지 기록한다. 담당자와 대리 승인자는 파일럿 시작 전에 실제 직책 또는 승인 가능한 식별자로 지정한다.

## 검토 시작 전 필수 입력

다음 항목 중 필수값이 없거나 서로 모순되면 엔지니어 검토로 넘기지 않고 `DATA/CONTRACT HOLD` 상태로 둔다.

| 분류 | 최소 입력 | 확인 목적 |
|---|---|---|
| 생산 건 식별 | 추적 가능한 run·Lot·wafer 식별자와 발생시각 | 모델 결과와 현장 기록의 동일 대상 확인 |
| 모델 증거 | 모델 버전·artifact 해시, 입력 snapshot 또는 해시, 점수 생성시각 | 사후 재현과 잘못된 버전 사용 탐지 |
| 우선순위 | risk score, 전체 순위, 선택된 Top-K 범위, 동점 처리 | 왜 큐에 포함됐는지 설명 |
| 데이터 상태 | 누락·지연·범위·단위·드리프트 검사 결과 | 불완전한 입력을 공정 이상으로 오해하지 않기 |
| 현장 문맥 | 실제 변수 사전, 공정 단계, tool·chamber·recipe 연결 | 익명·기술 변수에서 실제 조사 항목으로 안전하게 전환 |
| 품질 문맥 | 적용 중인 검사계획, 최근 검사 결과, 기존 hold·exception | 기존 품질 절차와 중복·충돌 방지 |

V1 데모는 위 현장 식별자와 변수 사전을 보유하지 않으므로, 현재 화면의 변수 중요도만 보고 실제 공정 원인을 추론할 수 없다.

## 건별 검토 절차

1. **큐 유효성 확인** — 생성시각, 데이터 최신성, 모델·입력 해시와 오류·드리프트 상태를 확인한다.
2. **대상 일치 확인** — 위험순위의 생산 건과 MES·검사 기록의 run·Lot·wafer가 동일한지 대조한다.
3. **기존 상태 확인** — 이미 hold, 재검사, 장비 alarm 또는 알려진 exception 대상인지 확인한다.
4. **공정 문맥 대조** — 실제 변수 사전을 통해 해당 신호의 단위·수집 위치를 확인하고 tool·chamber·recipe, 정비, 교대, 자재와 변동점 기록을 함께 본다.
5. **품질 증거 대조** — 해당 건과 유사 조건의 검사·defect 이력을 확인하되, 모델 중요도를 인과관계로 해석하지 않는다.
6. **판단 기록** — `추가 확인`, `기존 절차로 처리 중`, `현재 근거 부족`, `데이터 문제`, `에스컬레이션` 중 하나의 검토 상태와 근거를 남긴다.
7. **승인된 후속 조치** — 재검사·보류·설비점검 등은 현장 기준서와 승인권자에 따라 실행하며 모델이 자동 실행하지 않는다.
8. **결과 폐루프** — 최종 검사 결과, 실제 조치와 완료시각을 원래 모델·입력·판단 기록에 연결한다.

## 엔지니어 체크리스트

- [ ] 큐가 정해진 최신성 기준 안에 있고 `SYSTEM ERROR` 또는 계약 위반이 없다.
- [ ] 모델 버전·입력 해시·점수 생성시각을 확인할 수 있다.
- [ ] 생산 건 식별자가 MES·검사 이력과 일치한다.
- [ ] 해당 건에 이미 적용 중인 hold·재검사·exception을 확인했다.
- [ ] 모델 변수를 실제 변수 사전과 매핑했으며 단위와 수집 위치를 확인했다.
- [ ] tool·chamber·recipe, 정비·alarm, 자재·교대·변동점 기록을 필요한 범위에서 대조했다.
- [ ] 중요도 또는 상관 신호를 불량 원인으로 단정하지 않았다.
- [ ] 후속 조치, 근거, 승인자와 완료시각을 기록했다.
- [ ] 조치하지 않았다면 그 사유와 재검토 조건을 기록했다.

## 시간 목표와 우선순위 초안

실제 시간은 공장 기준과 점검 인력 자료로 정해야 하며, 아래 값은 성능 약속이 아니라 파일럿에서 측정할 **초기 운영 가설**이다.

| 큐 상태 | 초기 목표 | 처리 원칙 |
|---|---:|---|
| 계약 위반·해시 불일치·오래된 큐 | 사용 전 즉시 차단 | 엔지니어에게 그럴듯한 점수를 보여주지 않고 데이터·시스템 담당자에게 전달 |
| 기존 alarm·hold와 겹치는 고위험 건 | 교대 내 우선 확인 | 기존 품질·설비 절차에 결합하고 중복 조치를 피함 |
| Top-K 신규 검토 건 | 건당 10–15분을 가정해 측정 | 제한시간을 넘기면 억지로 결론내지 않고 `근거 부족` 또는 에스컬레이션 기록 |
| 비선정 건 또는 점검예산 초과 | 기존 절차 유지 | 모델 때문에 기존 필수 검사를 축소하지 않음 |

파일럿에서는 실제 중앙값·상위 90% 검토시간, 교대 내 미처리율과 에스컬레이션율을 수집한 뒤 목표를 조정한다.

## 최소 기록 계약

각 판단은 다음 필드를 감사 가능한 저장소에 남겨야 한다.

| 필드 | 예시 형식 | 비고 |
|---|---|---|
| `review_id` / `run_id` | 조직 내 추적 ID | 공개 저장소에 실제 생산 식별자를 올리지 않음 |
| `queue_generated_at` / `reviewed_at` | timezone 포함 timestamp | 큐 지연과 검토시간 계산 |
| `model_version` / `model_sha256` / `input_sha256` | 잠금평가 계약과 연결 | 재현 불가능하면 사용 중단 검토 |
| `rank` / `risk_score` / `top_k_policy` | 당시 표시값 | 사후 새 점수로 덮어쓰지 않음 |
| `data_status` / `drift_status` | pass, hold, warning | 경고를 검토 결과와 분리 |
| `review_status` / `reason_code` | 통제된 코드 + 짧은 메모 | 자유서술만 남기는 것을 피함 |
| `evidence_refs` | MES·FDC·검사·정비 기록 참조 | 원본 접근권한은 최소화 |
| `proposed_action` / `approved_action` | 제안과 승인을 분리 | 모델 제안과 사람 결정을 혼동하지 않음 |
| `reviewer_role` / `approver_role` | 역할 기반 식별 | 실제 이름·보존기간은 조직 정책 적용 |
| `final_outcome` / `outcome_available_at` | 최종 검사 결과와 확정시각 | 엔지니어 의견을 즉시 정답 라벨로 쓰지 않음 |

## 에스컬레이션과 종료 조건

다음 경우 건별 검토를 멈추고 관련 책임자에게 전달한다.

- 식별자·timestamp·단위·변수 매핑이 불명확하거나 서로 충돌함
- 모델·입력 버전 또는 감사로그를 재현할 수 없음
- 기존 품질 기준과 모델 큐가 충돌함
- 여러 Lot·tool·chamber로 영향이 확장될 가능성이 있음
- 재검사·보류·recipe 변경·설비 정지처럼 별도 승인이 필요한 조치가 제안됨
- 유사한 오경보·미탐·데이터 오류가 반복되어 시스템 문제로 의심됨

검토 건은 승인된 조치 완료, 근거 있는 무조치 결정, 기존 절차 이관 또는 시스템 hold 중 하나로 종료한다. 미해결 건을 단순 `정상`으로 닫지 않는다. 반복 실패와 전체 롤백은 [FAILURE_GOVERNANCE.md](FAILURE_GOVERNANCE.md)의 기준을 따른다.

## 접근권한과 보안

- 역할 수행에 필요한 MES·FDC·검사·정비 기록만 최소 권한으로 조회한다.
- 모델 담당자에게 품질 승인권을, 시스템 운영자에게 공정 해석 권한을 자동 부여하지 않는다.
- 실제 생산 식별자, 작업자 정보와 비공개 공정 데이터는 공개 저장소·일반 채팅·공개 이슈에 복사하지 않는다.
- 조회·판단·승인·변경 기록의 보존기간과 접근 검토 주기는 조직 정책으로 확정한다.

## 현장 적용 전 확정할 항목

- 실제 역할별 담당자·대리자·에스컬레이션 연락 경로
- 큐 최신성, 검토시간, 미처리율과 점검예산 기준
- 필수 변수 사전과 MES·FDC·검사·정비 시스템의 참조 방식
- reason code, 승인 상태와 최종 결과의 저장 위치·보존기간
- 개인정보·영업비밀·수출통제 등 적용 가능한 데이터 정책
- 모델 큐와 기존 SOP가 충돌할 때 우선하는 절차

이 항목이 승인되기 전에는 본 문서를 현장 SOP 또는 실제 배포 증거로 표현하지 않는다.
