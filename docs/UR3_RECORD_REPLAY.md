# UR3 실제 센서 기록 탐색·재생

## 먼저 읽기

두 번째 실제 로봇 데이터 사례로 UCI UR3 CobotOps를 추가했다. 기존 가상 R-01 이송 셀과 IMAD-DS 진동/SPC 분석은 유지한다. 이 화면은 **저장된 실제 센서 기록을 탐색·재생**하며 모델 예측·실시간 연결·로봇 제어·실제 동작 3D 재현을 하지 않는다. Python 백엔드를 호출하지 않는다.

최신 main `cce8360f`와 열린 PR 16개를 대조했으며 UR3 구현은 없었다. #179의 보고서 렌더러 404 격리 수정 `9d55b1fa`가 main에는 아직 없으므로 **이 PR은 #179 브랜치 위에 쌓은 별도 Draft**다. 검토 순서는 #179 → UR3이며 #179·#178을 병합하거나 수정하지 않았다. UR3 diff에 #179 코드를 복제하지 않는다.

## 화면 동작

`/robot/ur3/`에서 원본 행 순서를 유지한 JSON을 읽고 SHA-256과 스키마를 확인한다. 해시·형식·시간 순서 검사가 실패하면 결과를 비우고 재생 조작을 비활성화한다. 원본 결측은 null이며 상태 결측도 False로 바꾸지 않는다. 같은 origin의 정적 파일만 읽는다.

재생은 1행/초의 탐색 UI다. 실제 기록의 약1.005초 간격이나 수집 시스템의 실시간 동작을 재현했다고 표현하지 않는다. 5초 초과 시간 공백 직후 행에서 자동 일시정지하고 사유를 표시한다. 사용자가 다시 재생할 수 있으며 공백을 보간하지 않는다. 현재 행까지 최대120행의 센서를 실제 UTC X축에 그리며 결측/공백에서 선을 끊는다. 다른 센서 결측과 선택 센서 결측도 구분한다. cycle 감소는 별도 표시하되 독립 세션이라고 확정하지 않는다.

보호 정지·그립 손실은 별도 원본 상태 영역에 표시한다. 이 라벨은 모델 경보/고장 원인/제품 불량 확정이 아니다. 예측 지표 `anomaly_recall / false_alarm_rate / detection_delay`는 모두 null이다. 기존 1,043창·경보9/0/3 탐색 기록은 변경하지 않았으며 UR3와 합산하지 않는다.

## 재현과 검사

실행 환경 의존성을 늘리지 않기 위해 XLSX의 고정된 XML을 Python 표준 라이브러리로 읽는 빌더를 추가했다. ZIP/XLSX 해시가 맞지 않으면 중단한다. 원본은 덮어쓰지 않으며 JSON과 해시 모듈만 생성한다.

```bash
# 공식 ZIP을 별도 위치에 받은 뒤
python scripts/build_ur3_replay.py --archive /path/to/ur3+cobotops.zip
node --test tests/web/*.test.mjs
PYTHONPATH=src python -m unittest discover -s tests -v
python -m http.server 8764 --bind 127.0.0.1 -d web
# 설치된 허용 Chrome/Playwright 환경, 폭은1366/360/390 각각 실행
FABGUARD_BASE_URL=http://127.0.0.1:8764 FABGUARD_UI_WIDTH=390 FABGUARD_BROWSER_PATH=/usr/bin/google-chrome FABGUARD_UI_OUTPUT=/tmp/ur3-ui node verification/check_ur3_replay.cjs
```

CI는 공식 ZIP을 다시 받아 원본 해시를 확인한 뒤 재생 JSON과 해시 모듈을 바이트 단위로 재생성 대조한다. 브라우저 검사는 동일 head의 UR3, #179 renderer404/CSV4행, R-01, 정비 검토까지 포함한다. 실제 실행 결과는 해당 head의 CI/Drive 보고서로 연결하며 스크립트 준비만으로 통과라고 쓰지 않는다.

## 별도 단계로 제안하는 모델 평가 계획 (미실행)

1. 목표는 먼저 합의한다. 보호 정지/그립 손실의 **기록 상태 예측**과 실제 고장/불량 탐지는 다른 목표다. 실제 고장/onset/end와 정상 운전 라벨이 없으면 현장 이상 탐지 성능을 채우지 않는다. 현재 전체 기록을 탐색했으므로 같은 파일의 후속 평가는 탐색 연구이며 독립 확증으로 부르지 않는다.
2. 미사용 외부 기록 구간을 최종 확인용으로 별도 확보한다. 같은 파일에서 진단 실험을 할 경우 기록 시각 순서의 앞60%/다음20%/뒤20%를 후보로 제안하되, 실제 경계·buffer·창 길이·대상 정의를 **실험 전에 별도 계약으로 확정**한다. 인접 행 무작위 분할 금지. 경계는 연속 cycle run을 자르지 않도록 하되 반복 cycle 값 자체로 그룹을 합치지 않는다. 공백 구간/시각 의존과 세션 미확인 한계도 공개한다. 라벨을 본 뒤 유리한 경계로 이동하지 않는다.
3. 입력은 과거/현재의 실제 센서19개와 과거에만 의존한 특징으로 제한한다. 같은 시점/미래의 보호 정지·grip_lost 정답, Num, cycle을 센서 입력에 넣지 않는다. 전처리·임계값은 train/development에서만 적합·고정하고 최종 구간을 보며 반복 튜닝하지 않는다. IMAD-DS/SECOM 데이터와 무작정 합치지 않는다.
4. 누락/공백 제외·보류를 전체 분모와 함께 보고한다. 기록 상태 목표는 PR-AUC·고정 검토예산 포착률·recorded-state episode 단위 결과를 제안한다. 연속행을 독립 표본처럼 CI를 계산하지 않는다. 실제 오경보/시간·탐지 지연은 검증된 정상 구간과 onset/end가 확보된 뒤 평가한다. 수집간격 약1초의 시간해상도 한계를 함께 기록한다. 양성/정상 지원이 부족하면 미평가로 남긴다.

실제 휴대전화·스크린리더·외부 현장 일반화, 수집 장비 결속과 라벨 진위는 이번 구현의 통과 범위에 포함하지 않는다. 이 Draft의 병합·운영 배포는 별도 승인 대상이다.
