# IMAD-DS robot: independent raw-data reproduction and saved-file comparison

This is an offline reproducibility audit, **not a performance improvement**.
The original archive was independently downloaded, verified, extracted, and run
through the unmodified benchmark at
`e9c995bb95331abdb13da14b0fb93ccafc4cac78`. The resulting feature and prediction
CSVs were then compared directly with the previously retained reference files.

This documentation change was prepared from main
`cd7bf490a1d7ad3e53c77ea198e323b9d95c7ff3`; that publication base is distinct
from the code actually used in the reproduction. No benchmark rerun or model
fitting was performed to prepare this change.

## Archive and execution evidence

Source: [IMAD-DS v2, Zenodo record 12665499](https://zenodo.org/records/12665499).

| Check | Observed result |
|---|---|
| Archive size | 3,545,453,763 bytes |
| Official published MD5 | `a64498b7dcc297946a7fb8366e38ba33`, matched |
| Previously author-reported SHA-256 | `2d224895a083c9d1a12d9ad5817422e8a7428d0ee92b304929717595ead63b65`, matched |
| Extracted members | 6,915 files: 6,909 Parquet and six mapping CSVs |
| Extracted size | 7,194,000,084 bytes |
| Extracted member SHA-256 manifest fingerprint | `89d0a754de3233acdf0864d118d24c3ba7a9b8f92e51b4e23ad72109ade94ab2`, matched the author record |

The archive SHA-256 above is an author-reported comparison value, not a
Zenodo-published SHA-256. The original code checked all extracted member names,
sizes, CRC32 values, missing/extra files and symlinks. CRC32 is a general
corruption check, not cryptographic identity. The matching SHA-256 manifest is a
comparison with the author record, not an independently signed per-member list.
The older Git `report.json` predates the strengthened member fields; their
absence was not treated as a failed check.

The mapping, sensor schemas, file references and increasing relative timestamps
passed the original guards. The run produced 2,303 unique segments and 42 sensor
features. It fitted the unchanged seed-42 pipeline once for each of the two
fixed protocols, without using the 27 normal target-training segments. Output
was kept separate from the original results. Archive verification, extraction,
benchmark and comparison all exited zero. Verification plus extraction plus
benchmark took approximately 11 minutes 25 seconds, excluding download; the
benchmark subprocess itself took approximately 204 seconds.

## Direct CSV comparison

The [aggregate JSON](../results/robot-imad-2026/independent_file_comparison.json)
was generated by [the saved-file verifier](../verification/compare_robot_files.py).
The private reference CSVs exist in retained storage; they were not present in
the first local reproduction and were supplied for this follow-up. Neither
those CSVs nor the reproduced full CSVs are committed here.

| Input | SHA-256 |

| Reference features | `6d810ca6c3dcb9fabdc0487fc567eb31698aeeaec512c7d6a886f34d0edaa9d9` |
| Reproduced features | `cf5f49d2394aa31be57b65b889739560716498025b50d3d3fccbd7cf7ed520ad` |

Both feature tables have 2,303 rows and 48 columns: six metadata columns and
42 numeric features. Both prediction tables have 928 rows and seven columns,
with 464 rows per protocol. Column order, row-key order, key sets and all
metadata agree. There are no duplicate, missing or extra keys. Numeric values
were parsed directly from CSV strings using Python `float`.

| Values compared | Exact numeric differences | Maximum absolute error | Maximum relative error, nonzero reference |
|---|---:|---:|---:|
| 96,726 feature values | 14,231 | 9.094947017729282e-13 | 7.532082865129787e-14 |
| 928 prediction scores | 38 | 1.1102230246251565e-16 | 2.1698175971303836e-14 |

All values are finite. No zero reference value became nonzero. All comparisons
pass the combined `atol=1e-14, rtol=1e-14` check; this does not mean that every
absolute error is below 1e-14. The files are **not byte-identical or exactly
numerically identical**. LF/CRLF normalization alone does not make the feature
hashes match, so the difference is not attributed solely to Windows newlines.

With the original ordering rule (descending score, then ascending segment ID),
all six full ranking sequences agree: zero moved IDs and zero rank displacement.
The selected top-budget sets and captured-anomaly sets agree exactly. There are
no exact score ties, including across any inspection cutoff, in either file.

## Metrics and claim boundary

Each row below was recomputed separately from each saved prediction file.
AUROC and AP deltas are exactly zero; inspected counts, captured counts, recall
and false alarms also agree. These values agree with the original persisted
benchmark report and the independently generated report.

| Protocol | Domain | AUROC | AP | Captured anomalies / inspected | False alarms |
|---|---|---:|---:|---:|---:|
| Published split | source | 0.682372175980975 | 0.6668252672340897 | 19/24 | 5 |
| Published split | target | 0.5204369797859691 | 0.4619428863451408 | 0/24 | 24 |
| Published split | combined | 0.6019433709869204 | 0.531288992452239 | 18/47 | 29 |
| Disjoint recording groups | source | 0.6557669441141498 | 0.5881236527678033 | 9/24 | 15 |

| Disjoint recording groups | combined | 0.565825653983353 | 0.5017276675033764 | 11/47 | 36 |

Each individual domain contains 116 anomalies. In the disjoint target case,
only **one of 116 anomalies was found in 24 inspections**, with 23 false alarms.
Reproducing that poor result does not establish operational suitability.
The same 464 previously exposed test segments were reused; this is not a new
independent evaluation. Recording-group names do not prove physical independence
of acquisition dates, devices, installations or operators. Sensor reference and
relative-time checks do not independently prove simultaneous acquisition.

## Environment differences and remaining uncertainty

| Package | Original recorded environment | Independent environment |
|---|---|---|
| Python | 3.12.14 | 3.11.16 |
| NumPy | 2.3.5 | 2.2.6 |
| pandas | 2.2.3 | 2.3.3 |
| scikit-learn | 1.8.0 | 1.9.0 |
| pyarrow | 26.0.0 | 25.0.0 |
| joblib | 1.5.3 | 1.6.0 |

The independent run used Windows and py7zr 1.1.4. Its existing environment was
preserved; the missing archive dependency was isolated separately. These
differences are possible contributors to small numerical or serialized-byte
differences, **not an isolated or established cause**. No environment sweep or
model fitting was done to force matching hashes.

Both model-file hashes differ from the historical record. Historical model
objects were not compared, so tree structure, thresholds and sampled training
rows are not proven identical. Matching near-equal scores, exact rankings and
metrics cannot substitute for a model-internals comparison. The cause of the
model hash difference remains unverified.

## Recheck the retained files

Using the exact retained CSV bytes and an installed project environment:

```bash
python verification/compare_robot_files.py \
  --reference-features /private/reference/segment_features.csv \
  --reproduced-features /private/reproduced/segment_features.csv \
  --reference-predictions /private/reference/test_predictions.csv \
  --reproduced-predictions /private/reproduced/test_predictions.csv \
  --output /private/new-comparison.json
```

The script checks the four recorded input hashes, refuses an existing output,
and writes only aggregate evidence. It neither fetches data nor loads or trains
a model. Its synthetic tests cover row reordering versus metadata differences,
cutoff ties, near-equality versus exact equality, and wrong input hashes.
CI can check those semantics without the retained private files. Public JSON
and docs exclude local personal paths, storage links, credentials, row-level
data and model objects. Codex prepared this audit and its validation script;
the findings do not claim unaided manual implementation or field validation.
