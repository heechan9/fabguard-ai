## 1. 이미 있는 기능과 차이

| 검토 항목 | 확인한 구현 | 아직 없는 로봇 기능 |
|---|---|---|
| 입력 출처·형식 | #162 `load_mapping`, `verify_archive_members`는 공식 아카이브 MD5, 추출 멤버 이름·크기·CRC32, 센서 파일명·중복·존재·라벨·분할 수를 확인한다. | 임의의 신규 로봇 자료를 수용하는 범용 계약은 없다. 원본 파일의 진위, 센서 고장 진단도 입증하지 않는다. |
| 시간·결측 | #162 `sensor_features`는 각 Parquet의 `Time` 유한값·엄격한 증가를 요구한다. `channel_features`는 채널별 유효율을 기록하고 전부 무효인 채널을 NaN으로 남긴다. 학습 전체에서 비어 있는 특징 열은 거부하며 나머지는 훈련 정상 자료에 적합한 대치기로 처리한다. | 마이크·가속도·자이로 **간** 공통 시각, 시작/종료 범위·동기화, 구간별 전부 결측 채널이나 낮은 유효율의 보류 판단은 없다. 현재 파일은 각 센서의 상대시간만 담는다. |
| 조건·점수 | `domain_shift_op`(하중)과 `domain_shift_env`(배경)를 저장하고, 정상 source 훈련에만 적합한 IsolationForest의 점수·상위 10% 포착을 보고한다. 엄격한 세션 분리 훈련도 있다. | 학습하지 않은 조건의 보류 게이트, 신규 입력의 상태 계약, 정상/고장 진단은 없다. 상위 10%는 시험의 점검 예산이지 상시 경보 임계값이 아니다. |
| 인접 기능 | main의 Fledge 운용 슬라이스는 중복·지연·연결 끊김을 다루고, 제조 SPC 점검 흐름은 `unknown`·검토 큐를 사용한다. | 두 모듈이 IMAD 로봇 신호에 연결된 것은 아니다. 화면·문구 패턴만 검토해 재사용한다. |

[#163의 저장 특징 커버리지 감사](https://github.com/heechan9/fabguard-ai/pull/163)에서 엄격한 세션 분리 훈련은 214구간·14그룹이며 하중 `weight20`은 0구간이다. 제공 분할 훈련에는 `weight20`이 있다. 따라서 **사용한 훈련 프로토콜을 명시하지 않은 단일 조건 허용 목록은 틀리다.** Target 하중 25·30·35와 배경 B·E·G는 정상 source만 적합한 두 모델의 훈련 조건에 없다. 하중 00도 엄격 훈련에서는 네 배경 합계 16구간으로, 조합의 존재만으로 충분한 성능을 뜻하지 않는다. 로봇 특징 CSV의 메타데이터는 하중·배경이며 속도 열은 없다. 속도를 임의로 보충하지 않는다.

## 2. 제안하는 보수적 상태 계약

정상/이상 이진 판정을 추가하지 않는다. 신규 **오프라인 자료**를 처리하는 향후 별도 슬라이스에서만 아래 상태를 도입한다. 판단 근거로 모델 버전·훈련 프로토콜·조건 목록·입력 해시를 함께 보존한다.

| 우선순위 | 상황 | 반환 상태와 처리 |
|---:|---|---|
| 1 | 아카이브/매핑/센서 파일이 없거나 중복, 필수 열·라벨·상대시간 단조성 위반 | `invalid_input`: 점수 계산 중단, 검증 실패 사유와 파일·구간 식별자 기록. 현재 엄격한 원본 검사 실패를 완화하지 않는다. |
| 2 | 필수 하중·배경 누락/미확인, 구간의 필수 센서 채널 전부 무효, 품질 근거 부족 | `review_required_input`: 점수 공개 보류, 어떤 필드·센서가 불확실한지 기록. 결측은 로봇 고장이라는 뜻이 아니다. |
| 3 | 선언된 하중×배경 조합이 **선택한 모델의 실제 훈련 자료**에 전혀 없음 | `review_required_condition`: 점수 공개 보류, 미학습 조건과 참조 훈련 프로토콜을 기록. 정상이라고 표시하지 않는다. |
| 4 | 위 점검 통과 | `offline_rank_only`: 순위 점수를 사람이 점검할 근거로만 제시. 낮은 점수도 정상 인증, 자동 경보 해제, 로봇 제어를 의미하지 않는다. |

우선순위 2의 수치 기준(부분 결측률, 최소 샘플, 길이 차이, 허용 시간차)과 우선순위 4의 경보 기준은 **이번 문서에서 정하지 않는다.** 채널별 표본 수·기간·유효율 분포와 센서 시계 계약을 새 검증 자료에서 확인하고 사전에 고정해야 한다. 일단 전부 무효인 필수 채널, 누락 조건, 학습 자료에 없는 조합은 명확한 보류 사례다. `invalid_input`은 현재 파서의 구조 오류에 해당하므로 품질 보류로 덮지 않는다.

세 센서의 `Time`은 각각 상대시간이다. 범위가 비슷해도 같은 물리 시각에 취득됐다고 단정할 수 없다. 공통 시작시각·동기화 오차 계약이 없다면 교차 센서 시간 일치는 `not_verifiable`로 기록하고, 센서 융합의 동시성 또는 이상 발생시각을 주장하지 않는다. 센서 고장과 로봇 이상을 **진단상 구별**하려면 독립 센서 상태 근거 또는 라벨이 별도로 필요하다.

## 3. 구현 시 테스트 사례 (아직 실행하지 않음)

테스트는 작은 합성 매핑·Parquet/배열과 고정된 훈련 조건 목록으로 작성한다. 공개 시험 464구간의 라벨·점수를 보며 규칙을 바꾸지 않는다. 같은 조건이라도 선택한 프로토콜이 바뀌면 다른 상태가 나오는지 확인한다.

| 사례 | 입력 또는 설정 | 기대 결과 |
|---|---|---|
| T01 | `weight20`·`BckgA`, 엄격한 세션 분리 훈련 목록 | `review_required_condition`; 점수 공개 없음. |
| T02 | T01과 동일, 제공 분할 훈련 목록 | 조건 미학습 보류에는 해당하지 않음. 다른 품질 검사 통과 시 `offline_rank_only`; **정상 판정 금지**. |
| T03 | `weight25`·`BckgB`, source 정상만 학습한 두 프로토콜 | 둘 다 `review_required_condition`; target 시험 성능으로 허용 목록 확대 금지. |
| T04 | 하중 또는 배경 누락, 또는 지원하지 않는 `speed`만 전달 | `review_required_input`; 속도값을 하중으로 해석하지 않음. |
| T05 | 센서 매핑 파일 누락·중복·ID 불일치 | 현재 계약대로 `invalid_input`; 점수 없음. |
| T06 | 한 Parquet의 역행·중복·NaN 상대시간 | `invalid_input`; 센서·구간·사유 표시. |
| T07 | 한 구간에서 필수 마이크 채널 전부 NaN, 다른 구간은 유효 | `review_required_input`; 대치값으로 정상처럼 통과시키지 않음. |
| T08 | 한 센서의 일부 결측 또는 표본 수·기간 차이 | 관측 수치를 별도 품질 근거로 남김. 수치 보류 경계는 새 자료 확보 전 임의로 고정하지 않음. |
| T09 | 각 센서의 `Time`은 증가하지만 공통 절대 시작시각 없음 | 동기화 `not_verifiable`; 서로 같은 시각에 이상이 났다는 문구 금지. |
| T10 | 기존 훈련 조합, 구조·필수 품질 정상, 점수 낮음 | `offline_rank_only`; `normal`, `safe`, 자동 해제/정지 반환 금지. |
| T11 | 입력 구조 오류와 미학습 조건 동시 발생 | 우선순위 1의 `invalid_input`; 오류 사유를 감추지 않음. |
| T12 | 학습 프로토콜만 전환 | 해당 프로토콜의 조건 목록·버전으로 다시 판단하고 상태·근거가 일관되게 갱신됨. |

이 표는 기능 구현 후의 단위·계약 테스트 명세다. 원본 7z 재현 시험, 새 세션 성능 평가, 실제 브라우저 클릭 시험을 대신하지 않는다.

## 4. 그다음 단계와 데이터 요구

1. **독립 검증:** 기존 시험 464구간은 이미 결과가 공개됐다. 새 정상·이상 녹화를 날짜·장비·세션 단위로 잠그고 하중×배경별 독립 그룹 수를 먼저 공개한다. `normal_target_train` 27구간을 적응에 쓴 뒤 기존 target 정상 시험 116개를 독립이라고 말할 수 없다(96개가 녹화 그룹 겹침). 새 자료가 없으면 성능 향상 주장을 하지 않는다.
2. **경보 빈도:** 현재 top-10%는 232구간 중 24구간을 고른 사후 점검 예산이다. 연속 운전 시간·자연적인 이상 빈도·검토 가능 용량·사람이 확인한 오경보/누락 기록 없이는 시간당 경보·재알림·임계값을 확정하지 않는다. 신규 검증 자료로 정한 기준을 별도 잠금 평가에서 확인한다.
3. **센서 변화 화면:** 지금의 42개 요약 특징은 센서별 구간 통계이지 변화 시각·물리 원인 증명이 아니다. 원본 시계열 및 동기화 근거가 확보되면 센서별 값·시간 범위·결측을 보이는 **관찰 화면**을 제안한다. 센서 기여도를 고장 원인이나 안전 제어 지시로 표시하지 않는다.

**범위:** 로봇 웹 연동, 실장비 사용, 자동 정지·제어, 속도 추정, 기존 시험셋 반복 튜닝은 이 설계에서 수행하지 않는다. #162·#163은 dot·Claude 검토 대상으로 그대로 둔다. 두 PR의 병합 여부는 dot 판정과 사용자 승인 후 Claude가 처리하는 별도 절차다.
