# 현장 대응 연결과 평가 계획

**상태: 제안 문서. 새 기능·실험·현장 성과가 아니다.** 기존 모델, 데이터 분할, 점수, 임계값과 정본 결과를 변경하지 않는다. 이 문서는 경보를 실제 고객 현장의 검토 업무에 연결할 때 필요한 책임과 증거를 정의한다.

## 현재 구현과 제안의 경계

| 구분 | 확인할 근거와 경계 |
|---|---|
| SECOM 품질위험 프로토타입 | 생산 건의 위험순위·익명 변수 점검 후보를 제공하는 오프라인 연구다. [정본 결과](../results/v1/RESULTS_SUMMARY.md)와 [시험 노출 이력](TEST_EXPOSURE.md)을 함께 읽는다. 실제 고장 탐지, 수율·가동률 개선의 증거가 아니다. |
| 제조 검토 슬라이스 | [합성 이벤트→검토 감사 CLI](MANUFACTURING_REVIEW_SLICE.md)와 [정비 이력 검토](MAINTENANCE_CONTEXT_REVIEW.md)는 구현되어 있다. 원본 대조·보류·검토 기록은 지원하지만, 인증된 현장 승인·물리적 조치 완료·조치 효과를 입증하지 않는다. |
| 로봇 R01 데모와 별도 로봇 연구 | SECOM과 독립된 데모이며 실제 생산 제어가 아니다. [IMAD 오프라인 실험](ROBOT_IMAD_BENCHMARK.md)의 수치도 R01 데모 또는 실제 장비의 탐지 성능으로 전용하지 않는다. |
| 아래 현장 대응·평가 계획 | 실제 센서/정비 원본, 라벨, 담당 권한과 독립 평가 자료를 확보한 뒤 별도 승인해야 한다. 아래 항목을 적었다고 저장 스키마나 현장 연동이 구현되는 것은 아니다. |

학습 자료의 변수 분포·결측·그룹 차이는 탐색적 설명이며 독립 검증이나 원인 증거가 아니다. 관측값만의 분포 설명과 결측 처리 후 모델 입력도 구분한다. 다른 검토에서 추가된 설명 통계는 이 문서의 새 성능·조치 효과로 합산하지 않는다.

## 경보 → 근거 → 사람 검토 → 대응 기록

여기서 경보는 **점검 후보 신호**다. 품질 Fail 확정이나 설비 고장 진단이 아니다. SECOM 점검 순위, SPC 이탈, 자료 누락은 서로 다른 신호로 표시한다.

| 단계 | 제안하는 업무와 최소 기록 | 담당·진행 조건 |
|---|---|---|
| 1. 경보 접수 | 원본 기록 ID, 출처, 이벤트/수신 시각·시간대, 신호 유형, 모델/규칙 버전, 임계값 또는 Top-K 예산. 반복 알림은 원본을 보존한 채 별도 사건 ID로 묶음 | 현장 접수 담당. 연결 키·시간·단위가 없으면 정상 판정하지 않고 근거 부족으로 보류 |
| 2. 근거 묶음 | 원본 위치/해시, 사용 가능 시각, 결측·교정·정비 변경 이력, 기준선 적용 가능 여부, 관련 검사 결과. 점수 당시 이용할 수 없던 정보는 사후 근거로 구분 | 데이터/설비 담당. 익명 변수를 실제 센서로 추정하거나 상관을 원인으로 바꾸지 않음 |
| 3. 사람 검토 | 검토자 역할·시각·이유, 추가 확인/보류/점검 제안, 모델과 다른 판단 및 이유. 접수와 검토 완료를 구분 | 지정 엔지니어. 인증·권한 확인은 별도 필요. 모델이 recipe 변경·설비 정지·출하 승인을 실행하지 않음 |
| 4. 대응·결과 기록 | 제안, 승인, 실제 수행, 결과 확인을 별도 상태로 유지. 담당자·예정/수행 시각, 작업 기록 ID, 최종 품질 근거, 미해결 사유·다음 확인일 | 사업장 승인자와 수행 담당. 기록이 없으면 수행/해결로 표시하지 않음. 결과 피드백은 자동 재학습·임계값 변경을 유발하지 않음 |

현장 검토자와 공동으로 신호 정의, 근거 묶음, 알람 예산, 인계 문구를 먼저 검토한다. 이견·누락·처리 실패도 기록하고, 한 번의 인계가 끝나도 미해결 항목은 명시적으로 남긴다. 실제 고장·안전 조치는 기존 사업장 절차와 권한을 따른다.

## 향후 평가 계약: 점수 성능과 업무 부담을 함께 확인

**아래는 미실행 계획이며 새 결과가 아니다.** 현재 고정 평가 계약을 소급 변경하지 않는다. 현장 자료를 확보하면 독립 평가 전에 라벨 의미·확정 시각, 관찰 기간, 사건/생산 건 단위, 중복 묶음 규칙, 비교 절차, 담당자와 허용 기준을 문서로 동결한다. 같은 장비·LOT·세션의 연관 자료가 개발/평가에 섞이지 않도록 분할하고, 기존 시험 노출을 공개한다.

| 질문 | 사전 정의할 측정값 | 해석·보고 규칙 |
|---|---|---|
| 불필요한 알람은 얼마나 되는가? | 최종 라벨이 확인된 건의 FP/(FP+TN), 알람 중 FP/(TP+FP), 각 분자·분모 | 정상 중 오경보율과 알람 중 오경보 비율을 혼동하지 않는다. 미확정 라벨은 정상으로 간주하지 않고 별도 건수 보고 |
| 놓치는 Fail/고장은 얼마나 되는가? | FN/(TP+FN)과 TP/(TP+FN), 원래 라벨 정의와 건수 | SECOM Fail은 설비 고장 라벨이 아니다. 실제 고장 사건 평가에는 고장 정의·관찰 종료/지연 라벨 처리가 별도 필요. 분모가 0이면 정의 불가로 표시 |
| 엔지니어가 감당할 수 있는가? | 원시 알람 수와 중복 묶음 후 사건 수, 유효 관찰시간/교대당 검토 건수, 실제 검토 소요시간, 미처리 잔량·대기시간 | 관찰시간·담당 인원·결측 구간을 함께 보고. 점수만 있는 공개 데이터로 교대당 부담이나 대응시간을 만들어내지 않음 |
| 임계값/점검예산은 왜 그 값인가? | 현장 합의한 누락 허용치·검토 여력, 개발 자료에서 비교한 후보, 선택 이유와 승인 버전 | 개발 자료에서만 선택하고 독립 평가 전에 동결. Test 결과를 보고 재조정하지 않음. Top-K는 점검예산이지 확률 임계값/고장 확정이 아님 |

현재 절차와 제안 절차는 같은 평가 기간·대상·라벨 규칙·점검예산에서 비교한다. 총량뿐 아니라 장비/기간별 실패 사례, 미확정 라벨과 근거 부족 건수를 남기며 가능한 경우 독립 묶음 단위의 불확실성도 보고한다. 허용치 미달·과도한 미처리 부담·입력 품질 문제 시 운영 사용을 보류하는 기준을 평가 전에 정한다. 이는 현재 절차보다 우수하다는 선결론이 아니다.

수율·가동률·비용 개선은 위 탐지/부담 지표와 별도 결과다. 실제 수행 이력과 적절한 대조·교란 요인 검토 없이 단순 전후 변화나 검토 기록을 개선 효과로 주장하지 않는다. 상세 조건은 [현장 인과효과 검증 계획](CAUSAL_FIELD_VALIDATION.md), [최소 파일럿 초안](MINIMUM_PILOT.md), [실패 대응](FAILURE_GOVERNANCE.md)을 따른다.
