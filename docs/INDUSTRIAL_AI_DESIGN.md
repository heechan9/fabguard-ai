# Industrial AI 운영 설계 노트

FabGuard V1의 실험 결과는 UCI SECOM 데이터와 저장소의 실험계약에서만 도출한다. 아래 외부 참고 범주는 모델 성능의 증거나 학습 데이터가 아니라, 결과를 제조 현장의 의사결정 흐름으로 연결하기 위한 설계 참고자료다.

## 참고자료

- 산업 AI의 확률적 출력과 결정론적 운영 가드레일에 관한 비공개 교육자료.
- 생산기술·생산관리·반도체 제조공정·스마트공장 정보계층에 관한 비공개 교육자료.
- 이현진·김명건, `스마트공장 지원사업 주요내용 및 효과 분석`, 한국수출입은행 해외경제연구소, 2022.
- 박양신·지민웅, `국내 중소·중견기업의 스마트제조 구축 실태와 성과`, 산업연구원, 2020.

비공개 교육자료의 슬라이드와 예시 수치는 저장소나 웹에 재배포하지 않는다. 공개 검증이 필요한 기술 주장에는 공개 데이터, 논문 또는 공식 문서를 별도로 사용한다.

## FabGuard에 반영한 원칙

| 산업 AI 관점 | FabGuard 적용 | V1 경계 |
|---|---|---|
| 확률적 모델은 불확실한 위험 신호를 출력한다 | 0/1 자동 판정보다 연속 `risk_score`와 순위를 제시한다 | 위험점수는 불량 확률의 완전한 보정값으로 주장하지 않는다 |
| 결정론적 체계가 AI의 행동 범위를 제한한다 | 점검예산 5%·10%·20%, 출력 형식, 익명 변수 표기, 인간 승인을 가드레일로 둔다 | 실제 공장 인터록·PLC·품질 기준서와 연동하지 않는다 |
| 산업 AI는 현장 행동으로 이어져야 한다 | 고위험 생산 건과 우선 확인할 익명 변수를 엔지니어 검토 큐로 제공한다 | 재검사·설비점검을 자동 실행하지 않는다 |
| 품질 판단에는 설명과 추적성이 필요하다 | 데이터 해시, 시간순 분할, 모델 선택, Top-K 결과와 생산 건별 근거 범위를 기록한다 | 중요 변수는 원인 또는 실제 센서 명칭이 아니다 |
| 생산기술은 품질·설비·공정·운영의 협업 문제다 | 후속 검토 시 실제 센서 매핑, 4M, 변동점, 품질 이력을 함께 대조하도록 안내한다 | SECOM만으로 4M 범주나 원인을 추론하지 않는다 |
| 생산관리 자원은 제한돼 있다 | 전체 점검 대신 Top-K별 부담·포착·누락을 비교한다 | 비용자료 없이 금액 절감이나 수율 개선을 계산하지 않는다 |
| 반도체 검사는 공정별로 서로 다른 계측·결함 항목을 다룬다 | 위험 순위는 후속 계측·검사 대상을 정하는 신호로만 사용하고, 실제 공정 단계와 검사 항목은 엔지니어가 확인한다 | 익명 변수 590개를 Particle, 막 두께, 식각률, CD, Overlay 등 실제 항목으로 임의 매핑하지 않는다 |
| 검사 결과는 공정 안정화와 수율 향상을 위한 피드백으로 활용된다 | 점검 결과와 엔지니어 판단을 기록하는 폐루프 운영을 향후 현장 검증 구조로 둔다 | V1은 재검사 결과 수집, 공정 피드백 실행 또는 수율 개선 효과를 검증하지 않는다 |
| 스마트 팹 AI는 데이터 품질·보안, 도메인 협업, 지속 운영체계를 함께 요구한다 | 데이터 출처와 실험계약을 기록하고 결과 해석을 엔지니어 검토에 연결한다 | V1은 생산 데이터 거버넌스, 접근통제, MLOps, 공장 시스템 통합을 구현하지 않는다 |
| 스마트공장 정보시스템은 현장 데이터와 운영 의사결정을 추적 가능하게 연결한다 | MES·FDC가 제공할 데이터를 위험점수와 점검 큐로 변환하는 목표 위치를 정의한다 | V1은 MES·FDC·검사시스템에서 데이터를 읽거나 결과를 쓰지 않는다 |
| 스마트제조 성과는 모델 지표와 제조·사업 KPI를 구분해 검증해야 한다 | PR-AUC·Top-K 포착률은 현재 증거로, 불량률·가동률·원가·수율은 현장 검증 항목으로 분리한다 | 공개데이터 실험에서 실제 제조 성과나 인과효과를 추정하지 않는다 |

## 인간 중심 점검 흐름

1. **Risk signal** - 모델이 생산 건별 연속 위험점수를 산출한다.
2. **Budget guardrail** - 현장의 점검 여력에 맞춰 상위 5%·10%·20% 범위를 선택한다.
3. **Engineering review** - 엔지니어가 익명 중요변수의 실제 센서·공정 매핑을 확인한다.
4. **Context check** - 4M, 변동점 기록, 품질 이력과 대조해 재검사·설비점검 여부를 판단한다.
5. **Human decision** - 최종 판단과 조치는 사람이 승인하고 결과를 기록한다.

## 스마트 팹 확장 조건

실제 생산환경으로 확장하려면 공개 익명 데이터의 오프라인 실험을 넘어 다음 조건이 필요하다.

- **데이터 거버넌스** - 센서·설비·Lot·공정 이력의 출처, 품질, 접근권한과 변경 이력을 관리한다.
- **도메인 매핑** - 익명 변수 대신 실제 계측 항목·공정 단계·설비·레시피와 추적 가능하게 연결한다.
- **지속 검증** - 데이터 드리프트, 순위 품질, 점검부담과 재검사 결과를 모니터링하고 재검증 기준을 둔다.
- **운영 통제** - 모델 출력은 승인 가능한 점검 큐로 제한하고, 최종 조치와 예외 처리는 엔지니어가 담당한다.

FabGuard V1은 위 조건의 필요성을 설계 문서에 명시하지만, 공개 SECOM 데이터에서 오프라인 위험순위화를 재현한 단계에 한정된다. 보안·접근통제, 온라인 모니터링, 자동 재학습, MES·FDC·APC·SPC 연동은 구현하거나 검증하지 않았다.

목표 정보 흐름, KPI의 증거 수준과 현장 도입 체크리스트는 [SMART_FACTORY_INTEGRATION.md](SMART_FACTORY_INTEGRATION.md)에 별도로 정리한다.

## 반도체 공정 맥락

반도체 제조공정 기초 자료는 웨이퍼 Fab의 산화·포토·식각·이온주입·박막·배선·CMP·세정과 이후 측정·검사, 웨이퍼 테스트, 패키징의 흐름을 이해하는 데만 사용한다. 공정별 계측 예시에는 Particle, 막 두께, 식각률, 면저항, 막 응력, 표면 결함, CD, Overlay 등이 포함되며, 실제 현장에서는 이 결과를 공정 안정화와 수율 개선을 위한 피드백에 활용한다.

FabGuard V1은 이 공정 항목을 직접 관측하지 않는다. 따라서 위험 순위가 높은 생산 건을 발견하더라도 특정 공정·설비·레시피·결함 원인을 지목하지 않으며, 실제 변수 사전과 추적 가능한 공정 이력이 확보된 이후에만 공정별 점검 절차와 연결할 수 있다.

고적층 메모리와 첨단 패키징은 정렬, 접합, TSV, 적층 응력 등 여러 제조·신뢰성 요인을 함께 관리해야 하는 확장 사례로만 참고한다. FabGuard V1은 HBM 또는 패키징 데이터를 사용하지 않았으므로 해당 공정에 대한 성능이나 적용 가능성을 주장하지 않는다.

## 표현 규칙

사용:

- 위험 기반 우선점검
- 후속 점검 후보
- 제한된 점검예산에서의 Top-K 포착률
- 엔지니어 의사결정 지원

사용하지 않음:

- AI가 불량 원인을 규명했다
- 중요변수가 실제 고장 원인이다
- FabGuard가 수율을 개선하거나 비용을 절감했다
- V1이 실시간 FDC/APC/SPC 또는 자동 제어 시스템이다
