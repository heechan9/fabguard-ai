## BOSCH: 실제 파일 감사

출처: https://zenodo.org/records/17122442 (v1), 제공자 TU Chemnitz / Fraunhofer ENAS 등. 공식 API 메타데이터의 라이선스 `cc-by-4.0`. [파일 URL·크기·MD5·SHA-256·감사 JSON](review/BOSCH_SOURCE_AUDIT_20261027.json).

- `Process_data.nc`: **96그룹·313,169행**. **31열 86그룹 / 44열 10그룹**, 서로 공통인 센서 이름은 31개다. 소개의 ‘31변수’를 전체 원본 스키마로 하드코딩하지 않는다. 44열 그룹의 추가 열을 임의 보간·다른 그룹에 채우지 않는다.
- 각 그룹 시간 중앙 간격은 약 0.2초다. 시간 역전/동일 간격 0건, **0.3초 초과 간격 69건**, 최대 약 **45.2초**. 이는 사전 정의한 감사용 간격 집계이며 이상 탐지 기준이 아니다. README의 ‘불규칙/누락 없음’ 설명을 그대로 검증 완료로 전이하지 않는다. 간격 원인은 미확인이다.
- 시간 변수 units는 `seconds since 1970-01-01 00:00:00 UTC`지만 실제 값은 그룹별 **0~829.95초** 범위다. 실제 2024년 UTC 시각이라고 표시하지 않는다. 그룹명 날짜는 공정일 키로만 쓰고, 값은 원시 시간 좌표로 보존한다. 실제 시작 시각과 동기화 의미는 제공자 확인이 필요하다.
- dictionary 해독 후 비유한 센서 값 0개. 시간 공백이 없다는 뜻은 아니다. 센서 단위는 별도 확인 전 이름만으로 가정하지 않는다.
- 89점 CSV: **7,832행 = 88웨이퍼 ×89점**, 10 LOT, 공정과 88키 연결 / 공정만 있는 8키. 원본 결측 추적 열 `postox_thickness_nan`에 빈 셀 **157개**가 있고, 보완된 `postox_thickness`는 빈 셀 0개다. 제공자가 사전/사후 산화막 두께를 IDW 보간한 사실을 표시한다. 89점 모두 독립 실측값으로 부르지 않는다.
- 9점 CSV: **684행**, 유효 키가 있는 **675행 =75웨이퍼 ×9점**, **키 없는 9행**. 순서/주변 웨이퍼를 보고 ID를 추정하지 않고 조인에서 제외·보존한다. 공정만 있는 21키. 유효 키의 공정 외 orphan은 두 CSV 모두 0개다.
- LOT 상태 XLSX는 10 LOT와 합계96웨이퍼, 측정 누락 메모를 제공한다. 표 중간에 합계·빈 줄·별도 NaN 요약표가 있어 전체 시트를 단일 학습 표로 취급하지 않는다. 원본 읽기만 수행했고 수정하지 않았다.
- 9점 측정은 실험일, 89점 측정은 **2025년 2월**의 후속 측정이다(공식 Readme.pdf §2.3). 측정 시점·도구가 달라 두 측정을 자동으로 같은 시점의 정답으로 섞지 않는다. 두께 단위는 문서의 µm 설명을 따르되 위치 X/Y 좌표의 단위는 별도 확인한다.

### 조인 계약과 보류

공정 그룹 `Day_YYYY_MM_DD_Wafer_NN`을 명시적 정규식으로 `YYYY-MM-DD_NN`에 대응한다. CSV experiment_key와 같은 경우만 연결한다. LOT 번호는 CSV/XLSX 근거로 확인하며 파일 순서에서 추정하지 않는다. 89개 위치를 89개 독립 생산 건으로 분할하지 않는다. 계측 누락 8웨이퍼·키 없는 9행·원래 결측과 보간 마스크를 별도로 유지한다. 규격 한계와 Fail 라벨이 없어 임의로 ‘불량’을 만들지 않는다.

다음 실험 전: 타깃(예: 관측 가능한 식각 깊이와 균일도)·측정 출처/보간 처리·공통센서·동작 단계 분리·공백 처리와 LOT/날짜 단위 분할을 먼저 동결한다. 공정의 주기적 가스 전환을 곧바로 이상으로 부르지 않는다. 10 LOT·누락 패턴을 반영해 학습/개발/시험 LOT ID를 고정한 다음에만 적합하고, 인접 행/같은 웨이퍼의 위치를 무작위 분할하지 않는다. 이번 파일들은 구조 감사에 노출됐으며 ‘완전 미노출 시험셋’이라고 주장하지 않는다. PCA·새 모델·성능 산출은 이번 범위에 없다.

## voraus-AD: 공식 소스만 검토

출처: https://github.com/vorausrobotik/voraus-ad-dataset
고정 소스 커밋: `a91a86a642d23df58833b792a53de01edfd81abe`.
직접 다운로드한 파일을 위 커밋 URL의 바이트와 다시 대조했다.

| 파일 | SHA-256 |
|---|---|
| voraus_ad.py | `be1571476a0d4caa2006e1ecc77c37b710516ebeee275d30edf9812eb52333d2` |
| README.md | `03bad22e8a0ec3dc69f8cf340dc5f9e857ff42928fbe0c061412ab22b1674388` |

- 데이터는 CC BY-NC-SA 4.0, 코드는 MIT로 구분돼 있다. 이번 PR에는 해당 원본·코드를 복사하지 않으며 공개 웹 탑재/재라이선스는 하지 않는다.
- `Signals.meta()`의 `time`, `sample`, `anomaly`, `category`, `setting`, `action`, `active`를 입력 센서와 분리해야 한다. 특히 anomaly/category/setting/sample은 정답·조건·식별자이므로 점수 입력에 넣지 않는다. action/active를 사용하려면 이용 가능 시점과 용도를 먼저 고정한다.
- `meta_constant()`는 sample/anomaly/category/setting이며 `extract_samples_and_labels`는 각 sample 첫 행의 라벨을 사용한다. 이 공식 로더 경로만으로 **시간별 고장 onset 정답이 있다고 할 수 없다**. active는 별도 동작 메타이며 곧바로 이상 발생 시각이 아니다.
- `load_pandas_dataframes`: setting을 variant로 이름 변경, **PRE_A(72) sample 전체를 train / 나머지 sample을 test**로 분리한다. `train_gain <1`은 random.sample로 학습 sample을 줄인다. 그대로 복사하지 않고 원래 분할을 보존한 뒤 학습 구간 안에서 별도 개발 구간·seed를 고정해야 한다.
- 공식 정규화는 학습 자료만 fit한다. 원본 감사 단계에서는 다운샘플링·padding·정규화를 적용하지 않는다. 특히 padding 옵션은 시험 시계열을 자르므로 원래 시간·길이·노출량을 검증한 후 결정해야 한다.
- 실제 Parquet는 이번에 받지 않았다. 따라서 정상/이상 개수와 12종 소개를 직접 재계산했다고 하지 않는다. 샘플 단위 판정 벤치마크 후보일 뿐, 현장 고장 성능이나 IMAD에서 학습한 모델의 외부 검증 완료가 아니다.

다음 원본 감사에서 sample 간 중복·정상 라벨·시각 단조성·cadence·조건별 분포·파일 해시·라벨 상수성부터 확인한다. 개발 기준으로 임계값과 경보 묶음 규칙을 고정하고 시험은 고정 뒤 1회 평가한다. onset/안정 정상 주석이 부족하면 탐지 지연·현장 오경보율은 null로 유지하고 sample 단위 지표와 분리한다.

## 재현과 검증

검사 전용 격리 venv에만 `netCDF4==1.7.5.1.post1`, `numpy==2.5.4`를 설치했다. 프로젝트 pyproject·모델·웹 의존성은 변경하지 않았다. 무작위 계산/학습 없음(seed 해당 없음). 기본 Python 3.12.14의 pandas 2.2.3/openpyxl로 XLSX를 읽기만 했다.

[이번에 받은 공식 API JSON 스냅샷](review/BOSCH_METADATA_20261027.json)을 `bosch-metadata.json`으로 복사한다(출처 `https://zenodo.org/api/records/17122442`). JSON의 files에서 감사 JSON에 기록된 7개 file의 links.self만 다운로드한다. 대형 Day_* OES 파일은 필요 없다. 각각 크기·공식 MD5를 대조하고 다운로드 바이트의 SHA-256을 비교한다. 공식 메타데이터와 바이트 일치는 제공자 진위나 과학적 정확성 전체를 보증하지 않는다.

```bash
/path/to/isolated/python scripts/audit_bosch_candidate.py --source-dir /path/to/downloads --output /tmp/bosch-audit.json
PYTHONPATH=src python -m unittest tests.test_bosch_candidate_audit -v
```

감사 스크립트는 파일 읽기·품질 집계만 하며 원본/모델을 수정하지 않는다. 잘못된 record·해시 불일치·빈 측정표는 실패하고, 빈 키·orphan·중복 위치는 별도로 집계한다. 로컬 전체 회귀: `PYTHONPATH=src python -m unittest discover -s tests -v` 291개 중 285통과·6생략·실패0([원문](review/DATA_CANDIDATE_20261027_python.log)); `node --test tests/web/*.test.mjs` 120통과·실패0([원문](review/DATA_CANDIDATE_20261027_web.log)). 생략6개는 공식 SECOM 원본1·선택 pyarrow3·선택 Frictionless2 부족이며 테스트를 완화하지 않았다. 신규 입력 감사4개는 모두 통과했다. 웹 변경이 없어 실제 브라우저 검사는 이번에 재실행하지 않았으며 기존 화면 근거를 이번 검사 수에 합산하지 않는다. 원본 NetCDF/XLSX/PDF 바이너리는 PR에 넣지 않고 URL·해시와 재현 스크립트를 남긴다.
