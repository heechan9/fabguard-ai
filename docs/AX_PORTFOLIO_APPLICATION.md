# FabGuard: 문제와 검증을 보여주는 포트폴리오

## 적용 범위

2026-09-17 사용자 제공 AX 포트폴리오 교육자료의 독자 관점, 근거 연결,
사람과 AI의 역할 구분 원칙을 FabGuard 소개 화면에 적용했다.
자료의 가상 사례·수치·채용 관련 주장은 프로젝트 성과의 근거로 사용하지 않았다.
원본 교재, 슬라이드 이미지, 예시 코드는 재배포하지 않는다.

이번 변경은 소개 화면과 그 근거 문서를 연결하는 하나의 작업이다.
새 학습, 데이터 추가, 평가 변경, 프레임워크·런타임 의존성 추가는 없다.

## 이 프로젝트에서 보여줄 판단

| 항목 | FabGuard에서의 선택 |
|---|---|
| 주요 독자 | 반도체 공정·품질·스마트제조 직무 검토자 |
| 전달할 역량 | 제한된 점검 여력을 문제로 정의하고, AI 위험순위의 유용성과 한계를 검증하는 과정 |
| 핵심 질문 | 어떤 생산 건부터 확인하며, 그 범위에서 무엇을 놓치는가? |
| 결과의 근거 | V1 결과 CSV와 실험계약, 테스트 노출 기록 |
| 확인 방식 | 실행 가능한 점검 목록, 원자료 링크, 역할 및 한계 설명 |
| 사람의 역할 | 저장소 기여 기록에 명시된 문제·범위 결정, 결과 검토, 공개·병합 판단 |
| AI의 역할 | 실험·평가 코드, 화면·문서·테스트 작성 보조 및 실제 변경 구현 |
| 아직 증명하지 못한 것 | 독립 제조 데이터 성능, 현장 수율·비용 개선, 실제 공정 원인 |

## 화면 변경

- 첫 소개 영역에 포착 수, 분모, 범위 밖 불량 수와 잠정 판정 이유를 함께 배치.
- 중복된 소개·건수 요약을 줄이고 결과 다음에 세 종류의 증거를 배치.
- 상세 제작 과정은 펼쳐 읽도록 하여 초기 정보량을 제한.
- `#process`로 제작 판단과 검증 근거에 직접 진입 가능.
- 모든 새 결과 건수는 기존 `web/data/summary.json`에서 계산한다.
- 잘못된 건수·분모 또는 잠정 상태 누락 시 검증 없이 결과를 표시하지 않는다.
- 원자료와 모델 파이프라인은 그대로 유지한다.

## 독자가 확인할 질문

1. 왜 자동 불량 판정이 아닌 점검 순위 문제인가?
2. 5건을 찾았다는 결과 옆에 19건을 놓쳤다는 사실을 왜 제시하는가?
3. 가상 체험과 실제 데이터 평가의 증명 범위는 어떻게 다른가?
4. 작성자의 결정과 AI가 구현한 부분을 어떤 기록에서 확인할 수 있는가?
5. 현장 적용을 주장하려면 어떤 독립 데이터와 운영 기록이 더 필요한가?

이 문서는 채용 효과나 실력 향상 수치를 주장하지 않는다. 실제 사용자 검수와
직무 면접에서의 설명 능력은 별도로 확인해야 한다.
