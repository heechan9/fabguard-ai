# FabGuard 1개 라인·2주 최소 파일럿 초안

상태: **현장 승인 전 shadow-mode 설계안**. 이 문서는 실제 공장 실행, 현장 성능 또는 수율·비용 개선의 증거가 아니다.

## 파일럿 목적

대규모 RCT나 전면 도입 전에 한 개 생산라인에서 2주 동안 FabGuard 큐를 기존 절차와 병행해, 안전하게 사용할 수 있는지와 더 큰 평가를 설계할 가치가 있는지를 확인한다.

- 모델은 생산 건의 점검 순서만 제안한다.
- 기존 필수 검사·hold·release·재검사 절차는 축소하거나 대체하지 않는다.
- 모델 출력으로 설비·recipe·생산 상태를 자동 변경하지 않는다.
- 2주 결과만으로 수율·불량률·비용의 인과효과를 주장하지 않는다.

## 고정 범위

| 항목 | 최소 설계 | 파일럿 전 확정할 값 |
|---|---|---|
| 장소 | 승인된 생산라인 1개 | 라인·공정 단계와 데이터 소유자 |
| 기간 | 준비·기준 확인 후 운영 2주 | 시작·종료 timestamp와 교대 범위 |
| 사용자 | 소수의 공정·품질 엔지니어 | 주 담당자·대리자·승인자 |
| 운영 방식 | 기존 절차 병행 shadow mode | 큐 노출 대상과 기존 SOP 우선순위 |
| 점검예산 | 교대별 사전 고정 Top-K | 실제 처리 가능한 건수 또는 비율 |
| 모델 | 시작 전에 잠근 단일 버전 | artifact·입력 계약·설정 해시 |
| 자동조치 | 없음 | UI·API가 조치를 실행하지 않음 확인 |

라인, 기간, Top-K, 모델 또는 라벨 정의를 중간에 바꾸면 변경시점과 이유를 기록하고 변경 전후를 하나의 고정 실험처럼 합치지 않는다.

## 시작 전 통과 조건

- 데이터 소유자와 공정·품질·운영 승인자가 지정되어 있다.
- 기존 절차와 모델 큐가 충돌할 때 기존 승인 절차가 우선한다.
- run·Lot·wafer 식별자와 event timestamp를 모델 입력·검사 결과에 연결할 수 있다.
- 실제 변수 사전, 단위, tool·chamber·recipe 매핑의 가용 범위를 확인했다.
- 모델·입력 해시, 큐 생성시각과 오류 상태를 기록할 수 있다.
- [도메인 전문가 검토 절차](DOMAIN_EXPERT_REVIEW.md)와 [실패·롤백 기준](FAILURE_GOVERNANCE.md)을 담당자가 검토했다.
- 비공개 생산 데이터가 공개 저장소·일반 채팅·공개 이슈로 복사되지 않도록 저장 위치와 접근권한을 정했다.
- 파일럿 중단 시 기존 절차만으로 즉시 운영 가능한지 확인했다.

하나라도 충족하지 못하면 2주 측정을 시작하지 않고 준비 상태로 되돌린다.

## 2주 실행 흐름

### 매 교대 또는 합의된 배치

1. 입력 계약·최신성·해시·드리프트 상태를 검사한다.
2. 오류가 없을 때만 잠긴 모델로 위험순위와 사전 고정 Top-K 큐를 생성한다.
3. 엔지니어는 기존 절차를 먼저 유지하면서 모델 큐의 확인시각을 기록한다.
4. 모델 추천과 실제 점검 여부를 분리해 기록한다.
5. 추가 점검·재검사·보류 제안은 승인된 현장 절차로 결정한다.
6. 최종 품질 결과가 나중에 확정되면 원래 큐·모델·사람 판단에 연결한다.
7. 미처리 건, 모델 순위 변경, 데이터 문제와 에스컬레이션 사유를 교대 인수인계에 남긴다.

### 중간 점검

- 매일: 데이터 오류, 오래된 큐, 미처리 건과 안전사건을 확인한다.
- 1주 종료: 점검부담과 기록 누락을 검토하되 모델·Top-K를 성과에 맞춰 소급 조정하지 않는다.
- 2주 종료: 잠긴 데이터 snapshot으로 사전 정의 지표를 산출하고 다음 단계 여부를 회의록으로 승인한다.

## 수집할 최소 기록

`review_id`, 생산 건 식별자, queue·review timestamp, 모델·입력 해시, 순위·점수·Top-K 정책, 데이터 상태, 모델 추천 여부, 실제 점검 여부, 검토 사유, 제안 조치, 승인 조치, 최종 결과와 확정시각을 연결한다.

엔지니어 의견을 즉시 정답 라벨로 사용하지 않으며, 점검된 건에만 결과가 빨리 생기는 선택적 라벨 문제를 확인하기 위해 기존 검사 결과 또는 사전 정의한 무작위 표본감사를 유지한다.

## 파일럿 지표와 해석

| 구분 | 2주 동안 측정 | 주장하지 않는 것 |
|---|---|---|
| 실행 가능성 | 큐 생성·확인률, 데이터 계약 통과율, 교대 내 미처리율 | 장기 안정성 |
| 작업부담 | 건별 검토시간 중앙값·상위 90%, 추가 점검 건수, 에스컬레이션율 | 인건비 절감 |
| 안전 | 기존 절차 우회, 잘못된 대상 연결, 오래된 큐 사용, 자동조치 발생 건수 | 무사고 생산 보장 |
| 순위 신호 | 기존 라벨 정의에 따른 Top-K 포착·precision·lift와 표본 수 | 인과적 불량 감소 |
| 사람 상호작용 | 추천 수용·변경·기각 비율과 reason code 완결성 | 엔지니어 생산성 향상 확정 |

표본 수가 작으므로 모든 비율에 분모를 병기한다. 결과는 탐색적 feasibility evidence로 보고하고, 점추정치만으로 배포 성능을 확정하지 않는다.

## 즉시 중단 조건

- 모델 큐 때문에 기존 필수 검사나 사람 승인이 생략됨
- 모델·입력 버전, 생산 건 식별 또는 timestamp를 재현할 수 없음
- 잘못된 Lot·wafer·tool에 점검 지시가 연결됨
- 오래된 큐나 오류 점수가 정상 결과처럼 표시됨
- 승인되지 않은 자동 보류·재검사·recipe·설비 조치가 실행됨
- 비공개 생산 데이터 또는 작업자 정보가 승인되지 않은 위치로 노출됨
- 반복되는 미탐·오경보·데이터 오류가 사전 승인 한계를 초과함

중단 시 새 큐 발행을 멈추고 기존 절차로 복귀하며, 증거를 보존한 뒤 [FAILURE_GOVERNANCE.md](FAILURE_GOVERNANCE.md)의 재개 승인 조건을 따른다.

## 종료 후 결정

| 결정 | 최소 근거 |
|---|---|
| 중단 | 안전·데이터 계약 위반이 해결되지 않거나 기존 절차를 방해함 |
| 수정 후 반복 | 기록·UX·점검예산 문제는 고칠 수 있으나 2주 증거가 불완전함 |
| 제한적 연장 | 안전 조건을 지키며 더 긴 기간의 안정성 확인이 필요함 |
| 비교시험 설계로 진입 | 실행 가능성·로그 완결성이 확보되고 독립 비교의 표본·배정 계획을 승인함 |

어떤 결정도 2주 파일럿만으로 현장 KPI의 인과효과를 입증하지 않는다. 효과 주장은 [현장 인과효과 검증 계획](CAUSAL_FIELD_VALIDATION.md)에 따라 비교조건, 분석 단위, 표본크기와 관찰기간을 별도로 사전 고정한 뒤 검토한다.

## 현장 승인 전 빈칸

- 라인·공정·교대 범위
- 담당자·대리자·중단 및 재개 승인자
- 모델·입력 계약 버전과 Top-K 점검예산
- 라벨 정의·확정시점·무작위 표본감사 방식
- 허용 가능한 지연·오류·미처리·점검부담 한계
- 로그 저장 위치·보존기간·접근권한

실제 조직 자료 없이 위 값을 임의로 채우지 않는다.
