# 개별 측정값의 통계적 이탈 검사

털보님 반도체 특강의 SPC/FDC 구분과 렛유인 신소재·에너지 강의의 공정 데이터 분석
관점을 참고해, **CSV를 입력받아 실행하는 독립적인 오프라인 검사**를 추가했다.
교재가 이 구현이나 수식을 제공했다는 뜻은 아니다. V1 모델·분할·평가와 분리돼 있으며
실시간 SPC/FDC 시스템이나 설비 제어 기능은 아니다.

## 실행

저장소 루트에서:

```bash
PYTHONPATH=src python -m fabguard.spc --input examples/spc_synthetic.csv --baseline-count 10 --data-role synthetic --output /tmp/fabguard-spc.json
```

예제는 직접 만든 무단위 합성값이다. 처음 10건으로 중심선 100, 관리한계 약
94.6809~105.3191을 고정한다. 이후 100은 범위 안, 110은 위쪽 이탈, 90은 아래쪽 이탈,
빈 값은 판단 보류로 보고된다. 이는 검출 성능 실험이 아닌 동작 확인 사례다.

## 계산·입력 계약

[NIST 개별값 관리도](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc322.htm)의
수식을 사용한다. 기준 구간 평균을 중심선으로 하고, 인접값 절대차의 평균을 MR이라 할 때
관리한계는 `평균 ± 3 × MR / 1.128`이다. MR 관리도나 연속점 패턴 규칙은 구현하지 않는다.

- CSV 열은 `timestamp,value`. 하나의 측정 항목·단위·공정 조건으로 한 파일을 구성한다.
- 시간대가 명시된 시각이 엄격히 증가해야 한다. 중복·역순은 정렬해서 숨기지 않고 거부한다.
- `--baseline-count`로 먼저 정한 앞부분만 기준 계산에 사용한다. 이후 값은 한계를 바꾸지 않는다.
- 기준 구간은 최소 10건, 결측 없음, 양의 변동이 필요하다. 10건은 예제 실행을 위한 최소 입력 조건이며, 산업 현장의 충분한 기준 표본 수를 뜻하지 않는다.
- 기준 구간에 한계 이탈이 있으면 이후 숫자에도 `baseline_review_required`를 반환한다. 이탈이 없어도 안정성이 검증됐다고 표시하지 않는다.
- 이후 빈 값은 `unknown`. NaN·무한대·잘못된 행은 입력 오류다. 한계와 같은 값은 범위 안이다.
- 출력에 입력 SHA-256, 기준 종료 시각, Python 버전, 실행 설정, 각 관측값의 상태를 보존한다.
- `observed/synthetic`은 사용자가 선언한 자료 역할이다. 프로그램이 출처 진위를 인증하지 않는다.

## 해석 경계

관리한계는 제품 규격 상·하한과 다르다. 이탈은 검토 신호이며 불량 판정이나 원인 규명이 아니다.
범위 안인 값도 품질 합격을 보장하지 않는다. Cp/Cpk는 계산하지 않는다.
사용 전에 담당자가 기준 구간의 적절성, 측정 체계, 간격, 독립성·분포와 운전 조건을 확인해야 한다.
누락·조건 변경·시계열 상관·다변량 관계를 이 단일 규칙이 해결하지 않는다.
익명 SECOM 변수를 온도·압력 등 실제 센서로 해석하거나 기존 홀드아웃으로 한계를 조정하지 않는다.

## 검증

`tests/test_spc.py`는 NIST 계산 예시 대조, 미래값 변경 시 한계 불변,
경계 포함, 결측 보류, 부적절한 기준 구간, 잘못된 CSV·시간순서 거부를 검사한다.
기존 모델의 PR-AUC·포착률·공정 개선 효과는 이 기능으로 새롭게 입증되지 않는다.

## 웹 장비 CSV 점검

`/equipment/`에서 기존 입력 검증에 더해 `CSV → SPC 점검 목록`을 실행할 수 있다. [합성 입력 예제](../web/equipment/data/spc-synthetic.csv)를 내려받아 CSV로 선택하고 데이터 출처를 `synthetic`으로 지정하면 기준 10건과 후기 3건(정상 범위 1, 위·아래 이탈 각 1)을 확인할 수 있다. 예제는 기능 확인용이며 현장 데이터가 아니다.

- 열 매핑: `board_id`, `pad_id`, `value`, 시간대가 있는 ISO 8601 `timestamp`, `lot_id`, `recipe_id`. 화면에서 장비 ID, 데이터 역할, 측정 항목과 원본 단위를 선언한다.
- 파일 전체에 한 장비·Recipe·패드 위치·측정 항목만 허용한다. CSV 순서에서 시각이 엄격히 증가해야 한다. LOT은 달라도 되지만 기준 구간의 운전 조건·측정 체계가 같다는 판단은 사용자가 별도로 해야 한다.
- 입력 검증에서 격리된 행이 하나라도 있으면 SPC 계산을 중단한다. 누락값과 잘못된 열을 제거해 좋게 보이는 구간을 만들지 않는다. 선택한 앞부분 기준은 최소 10건이고 후기 행이 하나 이상 있어야 한다.
- 기준 구간에 한계 이탈이 있으면 모든 후기 상태를 `baseline_review_required`로 보류한다. 그렇지 않으면 후기 한계 이탈을 원본 행·시각·LOT·기판·패드와 함께 `pending` 점검 목록으로 보여준다. 현재 화면에서는 사람의 판단·승인을 기록하지 않는다.
- JSON 내보내기는 원본 파일 **바이트** SHA-256과 목록 전체를 저장한다. 이것은 사용자 파일과 계산의 연결 증거이지, 출처 인증이나 제품 불량 판정이 아니다. 파일 내용은 서버로 전송하지 않는다.

브라우저와 Python의 교차검증은 공통 **개별값 관리한계 계산 함수**(`individuals` / `individuals_report`)에 한정된다. 웹의 열 매핑·입력 계약은 Python SPC CLI의 `timestamp,value` 2열 계약과 다르며, 신규 CSV 파이프라인 전체의 Python 교차검증을 수행했다는 뜻이 아니다.

이 경로는 브라우저 내 오프라인 선별이며 Python `manufacturing_review`의 Fledge 이벤트 계약·결정 감사와 별개다. 현장 장비 연동, 관리도 기준 안정성 검증, 제품 규격 판정, 검사 성능 평가를 완료한 것으로 표시하지 않는다.

## 웹 합성 체험

`/equipment/index.html#spc-demo`에서 예제 초기화·높은 값·낮은 값·결측 버튼으로 고정 기준과 이후 측정을 비교한다. 업로드 CSV는 이 체험에 입력되지 않는다. 브라우저 계산과 Python 원본을 같은 입력으로 대조하는 회귀 테스트를 유지한다. 모바일 그래프는 내부 가로 스크롤을 지원하고, 수치는 별도 표로 제공한다.
