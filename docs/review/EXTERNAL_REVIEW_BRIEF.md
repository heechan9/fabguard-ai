## 무엇을 검토받고 싶은가

FabGuard는 제한된 점검 여력에서 먼저 확인할 생산 기록을 제안하는 산업 AI 포트폴리오다.
공개 UCI SECOM 오프라인 실험을 중심으로 입력 품질·결과 재현·사람 검토 기록을 연결했다.
**문제 정의의 실무 타당성, 결과 해석의 과장 여부, 다음 검증 우선순위**에 대한 의견을 요청한다.

예상 검토 분량은 10–15분이며 모든 코드를 실행할 필요는 없다.
제조·품질 담당자는 질문 1·3·5, 데이터·ML 담당자는 질문 2·4·5를 우선 검토할 수 있다.

## 핵심 결과와 한계

| 항목 | 확인된 결과 | 해석 범위 |
|---|---|---|
| 평가 구간 | 시간순 Train 1,175건 / Test 392건, Test Fail 24건 | Test는 사전 스모크 실행에서 노출돼 잠정 결과 |
| 선정 모델 | Train-CV 선정 Random Forest; CV AP 0.2155 ± 0.0650 → 이후 Test AP 0.0935 | 시간 구간 간 성능 저하가 있으며 일반화 입증 아님 |
| 임계값 0.5 | TP=0, FP=0, FN=24, TN=368 | Fail 분류 용도로 운영 가능한 성능을 입증하지 못함 |
| 상위 약 10% 검토 | 392건 중 40건을 검토하면 Fail 24건 중 5건 포착: 20.8%, precision 12.5%, lift 2.04배 | 35건은 정상 라벨이며 Fail 19건은 선정 밖에 남음. 실제 검사 절감·수율 개선 실적 아님 |
| 별도 재계산 | 기존 평가 모듈 없이 저장 예측의 AP·혼동행렬·Top-K 일치 확인 | 산술 일치 검사. 새 추론·독립 데이터·외부 검토를 대체하지 않음 |

## 답변과 후속 처리

[답변 양식](REVIEW_RESPONSE_TEMPLATE.md)에 확인한 범위만 작성하면 된다.
판단할 근거가 부족한 항목은 “판단 보류”로 남길 수 있다. 프로젝트에 대한 포괄적인 인증이나 추천을 요청하는 자료가 아니다.
원문 의견, 작성자 해석, 구현 변경을 구분하고 수용하지 않은 의견도 사유를 기록한다.
검토자의 이름·소속·직접 인용은 공개 범위를 확인한 뒤 반영한다.
실제 공정 자료나 비공개 생산 식별자는 이 공개 저장소에 올리지 않는다.

프로젝트 문제 정의·우선순위·검수는 최희찬이 담당하며, 구현·테스트·문서화에는 Codex를 활용했다.
상세 구분은 [기여 기록](../governance/CONTRIBUTIONS.md)을 따른다.
