# 사출 실험 검증 강화 — 탐색적 후속 결과

운영 교체 권고: **없음**. 비교 기준과 진단은 강화했지만 전체 성능 개선은 입증하지 못했다. 기존 사출 1차 결과와 SECOM V1/Phase1 정본은 해시로 보존을 확인했다. 이 데이터는 SECOM과 다른 공정·스키마이며, 반도체 모델의 외부 성능 검증이 아니다. 이미 관찰한 후기 라벨을 다시 사용했으므로 독립 검증도 아니다.

## 고정한 비교 조건

상위 PROTOCOL.md의 정제·그룹 누출 차단·시간 분할을 유지했다. 학습 3,021건/불량 52건, 후기 2,209건/불량 8건. 3개 과거 날짜의 순차 검증에서만 후보와 임계값을 선택했다. 이번 PROTOCOL.md를 커밋한 후 실행 코드를 커밋하고 실행했다. 후보는 기존 Logistic/RF, 제품별 학습 불량률 기준선, 학습 1/99 분위수로 입력을 제한하는 Logistic, 제품명을 제외한 RF로 한정했다. 후기 결과에 따라 추가 튜닝하지 않았다.

개발 평균 AP는 제품 기준선 0.026975, Logistic 0.024370, RF 0.132812, 제한 Logistic 0.023376, 제품명 제외 RF 0.245402였다. 선택된 후보는 제품명 제외 RF다. 선택 기록은 후기 예측 전에 저장했다. 개발 성적이 후기 개선을 보장하지는 않는다.

## 같은 예산 비교

전체 기간 점수를 한꺼번에 정렬하는 상위 221건과, 각 날짜의 상위 10%를 배정하는 총 225건은 서로 다른 정책이다. 둘 다 사후 일괄 평가이며 실시간 도착 순서의 점검 정책 검증은 아니다.

| 후보 | 후기 AP | 전체 상위 221건 포착 / 8 | 정밀도 | Lift | 정상 점검(오경보) | 날짜별 총 225건 포착 / 8 |
|---|---:|---:|---:|---:|---:|---:|
| 제품별 불량률 기준선 | 0.015950 | 2 | 0.905% | 2.499 | 219 | 0 |
| 기존 Logistic | 0.003651 | 0 | 0% | 0 | 221 | 0 |
| 기존 RF | 0.049528 | 2 | 0.905% | 2.499 | 219 | 2 |
| 입력 범위 제한 Logistic | 0.019556 | 2 | 0.905% | 2.499 | 219 | 0 |
| 제품명 제외 RF | 0.025117 | 6 | 2.715% | 7.497 | 215 | 0 |

- **관측상 개선:** 제품명 제외 RF의 전체 기간 포착은 25%→75%. 제한 Logistic은 점수 포화와 전부 경보 현상이 완화됐다.
- **관측상 악화:** 제품명 제외 RF의 AP는 0.049528→0.025117, 날짜별 포착은 2→0이다.
- **차이 불명확:** 전체 기간 포착 개선의 날짜 군집 부트스트랩 95% 차이 구간은 [0, 0.625], AP 차이는 [-0.089968, 0.001036]. 둘 다 양의 개선을 입증하는 조건을 충족하지 못한다. 기존 RF와 제품 기준선도 상위 221건 포착 수는 같다.

2,000회 동일 날짜 재표집으로 대응 비교했다. 불량이 없는 161회는 AP/포착률/Lift가 정의되지 않아 제외했고 유효 반복은 1,839회다. 6일·불량 8건의 작은 표본이므로 이 구간 자체도 강한 일반화 근거가 아니다. 11월 4일을 제외하면 불량은 1건만 남고 모든 후보의 상위 10% 포착이 0이다. 날짜 제외 분석은 진단용이며 모델 선택에 쓰지 않았다.

동점 순서를 200회 바꿔 본 상위 221건 포착 범위는 기존 Logistic 0~4건(중앙값 1), 다른 후보는 각각 표의 값과 같았다. 공식 표는 기존 ID 동점 규칙을 유지했다. 좋은 동점 순서를 고르지 않았다.

## Logistic 전부 경보 진단

Average_Screw_RPM의 학습 범위는 약 290.400~293.900이며 후기 값은 전부 이 범위를 벗어났다. 기존 Logistic 전처리 후 이 변수의 절댓값 최대는 학습 2.273, 후기 273.908이었다. 후기 평균 logit 기여는 +41.094로 점수 포화에 크게 기여했다. 이것은 수치 진단이지 실제 회전수 이상·센서 고장·인과관계의 입증이 아니다. 물리 단위와 수집 체계는 별도 확인이 필요하다.

학습 구간에서만 계산한 분위수 제한 후 후기 확률은 약 0.028~0.951로 분산됐다. 임계값 0.5의 경보는 2,209건(불량 8/정상 2,201)에서 186건(불량 2/정상 184)으로 줄었다. 그러나 놓치는 불량은 늘고 날짜별 예산 포착은 여전히 0이다. 경보 감소만으로 성능 개선이라 부르지 않는다.

OOF 경보를 10% 이하로 제한해 고른 임계값도 후기 예산을 보장하지 않는다. 후기 경보는 Logistic 2,209건, RF 462건, 제한 Logistic 38건(불량 2/정상 36), 제품명 제외 RF 248건이었다. 이 임계값 결과를 고정 상위 221건 결과와 혼합하지 않는다.

변수별 logit 표는 선형 모델의 수치 기여 진단이며 개별 생산 건의 원인 설명 기능이 아니다. 제품명 제거도 민감도 실험이지 제품이나 센서의 인과적 효과 추정이 아니다. 설명 기능·운영 화면은 변경하지 않았다.

## 재현 및 남은 조건

실행 명령은 manifest.json에, 집계 결과는 results/에 있다. 원본 데이터·개별 예측은 배포하지 않았다. 데이터 출처·사용 조건은 상위 PROTOCOL.md와 REPORT.md를 따른다. 새 데이터 확보나 외부 연락은 수행하지 않았다.

기존 실험 테스트 6개와 강화 테스트 6개 통과. 강화 테스트는 학습 전용 클리핑·결측 처리, 제품 기준선/미지 제품, 동점 임계값의 예산, 제품명 및 사후 검사 사유 제외, 기존 산출물 해시 보존을 검증한다. 기존 Logistic/RF AP도 재현했다.

운영 반영 추천은 현재 없다. 향후 평가에는 신규 기간의 미노출 개별 품질 라벨, 안정적인 센서 정의·단위, 제품·설비·생산 그룹 식별, 측정 시점과 검사 시점, 실제 일별 점검 예산이 필요하다. 수집 전 처리 규칙과 예산 정책을 고정하고 불량이 여러 날짜에 충분히 포함되는 평가를 진행해야 한다. 새 데이터에서 재검증하기 전에는 현재 모델·정본을 교체하지 않는다.
