## 확인할 질문과 제한된 후보

기존 RF와 Logistic을 같은 seed/config로 재현하고 v1 AP와 점수를 대조한다. 새 후보/비교는 아래3개만 추가하고 결과 후 튜닝하지 않는다.

1. 제품 종류만으로 얻는 성능: 제품별 불량률 기준선. 각 fit에서 (제품 불량수+20×전체 불량률)/(제품건수+20); 미지 제품은 전체 학습 불량률. 제품별 빈도는 fit자료만 사용한다. alpha20 고정. 센서 신호의 추가 가치에 대한 더 엄격한 기준선이다.
2. H1 Logistic 포화 완화: 기존 L2 C=.1/balanced 유지. 학습 필터·중앙값 대체 후 각 측정변수를 학습 1%/99% 분위수로 clip하고 scaler fit. 추론은 같은 경계 적용. 이상치가 실제 불량 신호일 수 있으므로 손실도 그대로 기록. 분위수 추가 탐색 없음.
3. H2 RF 제품명 제외: 수치형 공정 변수만 같은 RF 설정에 사용. 이는 입력 제거 민감도 실험이지 센서의 인과효과 검증이 아니다.

개발 내부 검증은 v1과 같은10/22,23,27 확장구간. 평균 AP→평균Top10포착률→이름순으로 5개(candidate including product_prior)중 선택. 최종fit은10/29이전. 선택 JSON을 후기 예측 전에 저장. 기존 후보 결과와 후기 AP를 보고 추가 모델이나 설정을 고르지 않는다.

## 예산/임계값 구분

- 전체 후기 Top5/10/20%: 기존111/221/442건. 모든 후보 동일 예산, 동점ID순. 전체기간을 모아 순위화한 회고적 비교이므로 실시간 운영 성과 아님.
- 날짜별 고정10%: 날짜마다 ceil(.1×당일건수)를 적용하고 합계 예산·포착·오경보를 공개. 전체기간Top10과 정확한 K가 다를 수 있으므로 별도로 비교. 당일 생산 종료 후 일괄 점검 시나리오이며 실시간 경보와 구분.
- 임계값 .5 및 개발OOF 경보건수<=ceil(.1×OOF n) 제약 아래 F2 최대(동률 높은threshold). 필요시 최대점수보다 큰 threshold로0경보 허용. 테스트의 점수/라벨로 threshold를 보정하지 않는다. 실제 후기 예산을 지킬 것이라는 보증은 없음.

## 취약성·불확실성

각 후보 AP/Top10포착/정밀도/Lift와 RF 및 제품기준 대비 차이. 동일 날짜를 함께 재표집하는 paired day bootstrap2000회; 불량0은 AP/포착/Lift NA, 유효반복수 명시. AP와 포착 차이 하한 모두>0일 때만 이 표본 내 개선 근거; 그 외 차이 불명확. 적은6일 및2불량일, 재학습/선택 불확실성 미포함 한계 유지.

동점 처리는 ID순 외 seed고정 랜덤 tie-break200회 Top221 포착 최소/중앙/최대 기록. 점수값이 같은 건 사이에서만 섞고 성능 좋은 정렬을 선택하지 않는다. 각 날짜 및 제품별 성적·각 날짜를 하나씩 제외한 성적 공개(제외 결과를 새로운 성능으로 채택하지 않음).

Logistic 진단: fit/후기 점수 범위·포화 비율, 학습 측정범위 밖 비율, scaler 변환값 범위, 변수별 평균 로짓 기여 크기를 기록. 후기진단 결과는 본 가설의 설정을 수정하는 데 사용하지 않는다. 원인 확인 없는 단위오류·센서고장·인과 주장 금지.

신규 설명 기능/운영 모델/임계값 변경 없음. 원본/행별자료/회원워터마크 공개 없음. v1 PROTOCOL의 출처·활용조건을 그대로 따른다. 새 기간·LOT·검사 기준은 이 파일에서 복구할 수 없으며 확보되지 않은 것을 확보했다고 주장하지 않는다.
