OFFLINE CONTEXT REVIEW

정비 뒤에도 같은 기준선을 써도 될까요?

정비·교정·레시피 변경과 측정값을 함께 보고, 기준선 적용을 보류한 이유를 확인하세요. 같은 장비·공정의 이력만 연결합니다.

로컬 검토 초안입니다. 웹은 묶음의 표시 형식을 검사하며, 원본 대조·최종 검토 기록은 Python CLI 재계산이 필요합니다. 사람의 역할은 사용자 선언이며 인증된 승인·현장 제어가 아닙니다. 정상·불량 판정, 원인 확정, 수율·탐지 성능 검증을 하지 않습니다.

쉽게 말하면, 무엇을 확인하나요?

정비나 설정 변경 뒤에도 예전 참고 기준을 그대로 써도 될지 살펴보는 화면입니다. 변경 이력과 측정값을 함께 읽고, 근거가 부족하면 판단을 보류합니다.

정비 전후에 모델이 더 정확해졌는지 평가하는 화면은 아닙니다. 실제 정비 효과를 확인하려면 정비·재가동 기록, 웨이퍼·LOT 연결 정보, 입력값과 검사 결과를 처음 알 수 있었던 시각을 갖춘 별도 평가가 필요합니다. 이 화면의 합성 사례나 코드 검사 통과는 그 평가를 대신하지 않습니다.

1. 검토 묶음 열기

Python에서 원본 측정과 변경 이력으로 만든 JSON을 선택하세요. 최대 5MiB이며 이 브라우저 메모리에서만 읽습니다. 파일을 바꾸거나 지우면 이전 검토 초안도 지웁니다.

아직 파일을 열지 않았습니다.

2. 변경 이력과 참고 측정값

참고 관리한계(UCL/LCL)는 제품 규격(USL/LSL)이 아닙니다. 규격 적합성이나 Cpk를 계산하지 않습니다. 참고 관리한계는 다시 맞추지 않습니다. ‘조건 충돌 없음’도 공정 안정성·품질 합격을 뜻하지 않습니다. 정비 뒤 값이 달라졌다는 사실만으로 원인이라고 판단하지 않습니다.

좁은 화면에서는 표·그래프 안을 가로로 움직여 전체를 확인하세요. 키보드는 해당 영역에서 방향키를 사용하세요.

가로축은 이후 측정 시각, 세로축은 원본 단위입니다. 점선은 고정 참고 관리한계, 주황 세로선은 표시 구간의 변경 시점, 물음표는 결측입니다. 기준 구간 안의 변경은 아래 이력 표를 확인하세요.

동일 장비·공정의 변경 이력
변경 ID·종류효력 시각알게 된 시각구간·설명

이후 측정과 판단 보류 근거
측정 시각·값참고 SPC 결과조건 검토보류 이유·관련 변경

3. 사람 검토 초안

판단 보류 항목은 ‘근거 부족’으로 두고 보류·장비 확인·재검사만 제안할 수 있습니다. 해제는 설비 명령이 아니며, 이 화면에 사업장 승인 권한은 없습니다.

미작성 항목은 pending으로 남습니다. 내려받은 JSON은 원본 묶음 바이트 해시에 연결되며, CLI에서 원본 측정·이력을 다시 대조해야 감사 기록이 만들어집니다.

선택 항목의 추가 근거 정리 (선택 사항)

원본 검토 상태를 바꾸지 않는 자기기재 메모입니다. 신호 종류·계측 시각·조회 가능 시각과 경쟁 가설을 구분합니다. 입력 완료는 검증 완료나 조치 승인으로 바뀌지 않습니다. 대상·파일 변경 시 입력을 지우며 서버 전송·자동 저장은 하지 않습니다.

설비 신호와 후속 전기적 검사(ET)·수율 결과는 각각 기록하세요. 연결 근거가 필요하면 검증 계획에 사용할 LOT·웨이퍼 키와 시각을 적으세요.

추가 근거는 별도 신호나 계측 자료일 수 있어 위 표의 원본 관측 시각과 다를 수 있습니다.

어떤 조건에서 무엇과 비교하고, 어떤 결과가 나오면 가설을 다시 볼지 적으세요. 이미 확인한 결과는 아래 ‘검증 기록 참조’에 연결하세요.

    원본 판단·SPC 결과·보류 사유는 유지됩니다. 여러 측정 위치나 가설 하나만 남았다는 사실로 인과·전면 균일도·안전성을 입증하지 않습니다. 민감한 장비 정보나 개인 정보는 입력하지 마세요.
